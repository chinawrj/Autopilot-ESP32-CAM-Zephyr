## What Was Done

### Zephyr Workspace Setup
- Created `manifest/west.yml` pinned to Zephyr v4.1.0
- Used T2 topology with manifest subdirectory approach
- Cloned: zephyr, hal_espressif, hal_xtensa, mbedtls
- Fetched ESP32 binary blobs via `west blobs fetch hal_espressif`
- Installed Python requirements

### Project Scaffold
- `CMakeLists.txt` — standard Zephyr app structure
- `prj.conf` — GPIO, logging, PSRAM (8MB), heap config
- `src/main.c` — LED blink on GPIO33 using Zephyr DT GPIO API
- `boards/esp32_devkitc_wrover_esp32_procpu.overlay` — LED node on gpio1 pin 1
- `tools/provision-wifi.sh` — WiFi credential injection from env/file

### Build Issues Resolved
1. **CONFIG_ESP32_SPIRAM_HEAP_SIZE undefined** — Fixed to `CONFIG_ESP_SPIRAM_HEAP_SIZE`
2. **Missing hal_xtensa module** — Added to west.yml name-allowlist
3. **xtensa core-isa.h #include_next failure** — Patched `zephyr/arch/xtensa/core/CMakeLists.txt`
   to use `ZEPHYR_HAL_XTENSA_MODULE_DIR` and add Espressif HAL xtensa include path.
   Root cause: Zephyr v4.1.0 references `ZEPHYR_XTENSA_MODULE_DIR` but module registers as
   `ZEPHYR_HAL_XTENSA_MODULE_DIR`. New ESP toolchain (14.2.0) uses `#include_next` wrapper.
4. **Overlay file not found** — Renamed from `esp32_devkitc_wrover.overlay` to
   `esp32_devkitc_wrover_esp32_procpu.overlay` (HW Model v2 naming)

## Key Learnings
- Zephyr v4.1.0 HW Model v2 requires full board qualifier in overlay filenames
- T2 topology needs manifest in subdirectory to keep `.west/` at repo root
- ESP32 xtensa core-isa.h is in hal_espressif, not hal_xtensa — requires local patch
- Espressif toolchain path: `~/.espressif/tools/xtensa-esp-elf/esp-14.2.0_20241119/xtensa-esp-elf`
