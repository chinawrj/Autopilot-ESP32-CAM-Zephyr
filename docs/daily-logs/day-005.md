## Architecture Decisions

- **Listener + worker thread split**: Listener thread (2048B stack, prio 7) handles
  accept loop and serves static pages inline. Dedicated stream worker thread (3072B
  stack, prio 8) waits on semaphore, runs MJPEG capture/send loop.
  This lets the index page be served even while a stream is active.
- **Single-stream limit with 503**: Only 1 concurrent stream is supported. Additional
  stream requests get 503 Service Unavailable. Avoids resource contention on DRAM-tight system.
- **No net_buf increases**: Attempted TX_COUNT 48 + DATA_SIZE 512 → DRAM overflow by 2208 bytes.
  Even TX_COUNT 48 + DATA_SIZE 256 → overflow by 1184 bytes. Kept original values (TX_COUNT=32, DATA_SIZE=256).

## What Was Done

### Task 1: Timing Instrumentation

Added per-frame metrics to handle_mjpeg_stream:
- `cap_ms`: camera capture time (~250ms)
- `send_ms`: socket send time (~200-300ms)
- FPS and frame count logging every frame

Measured performance: ~2 fps, ~10-12KB frames, ~450-550ms per frame total.

### Task 2: HTTP Server Architecture Rewrite

Split single-threaded HTTP server into listener + dedicated stream worker:
- Listener thread: accept(), serve index page inline, hand off stream socket via semaphore
- Stream thread: k_sem_take(), run capture loop, close socket
- Socket ownership: listener creates all sockets; stream thread closes stream sockets
- 503 response returned immediately for concurrent stream requests

**Verified on-device**: Index page served while stream is active. Second stream correctly rejected with 503.

### Task 3: OV2640 AEC/AGC & DSP Brightness

Re-enabled AEC/AGC after JPEG configuration:
- COM8 = 0xE5 (AEC + AGC + banding ON)
- COM9 = 0x48 (AGC gain ceiling 32x)
- DSP register 0x9B = 0x20 (brightness +2)
- DSP register 0x9C = 0x28 (contrast boost)
- Added register readback diagnostics

Brightness improved slightly (mean ~13-18 vs ~3 before) but still dark — likely physical
environment limitation. Max pixel values occasionally reach 128-129, confirming data pipeline
is working (8-bit range, not clipped at 0x80).

## Known Issues

- **Dark images**: Brightness limited by physical environment. AEC/AGC and DSP tuning
  applied, but mean pixel values still low. Color bar test was not feasible (writing COM7
  after JPEG init crashes the device).
- **DRAM at 99.56%**: No room for net_buf increases or additional static allocations.
  Future features must budget DRAM carefully or move data to PSRAM.
- **High ping latency**: ~200ms avg ping to device, suggesting WiFi congestion or
  ESP32 network stack overhead.
