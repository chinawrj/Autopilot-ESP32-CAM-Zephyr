# Day 11 — WiFi Resilience & Server Lifecycle Fix

## Goals
1. Fix HTTP server boot dependency on WiFi — start server regardless of WiFi state
2. Add WiFi disconnect/reconnect tracking with stats in status API
3. Complete M5 milestone items

## Completed

### HTTP Server Lifecycle Fix
- **Bug found**: HTTP server only started if WiFi was connected at boot time
  (gated by `wifi_manager_is_connected()` check in main.c)
- **Problem**: If WiFi times out at boot but later reconnects via
  `CONFIG_ESP32_WIFI_STA_RECONNECT`, the HTTP server never starts
- **Fix**: Start HTTP server unconditionally (binds to INADDR_ANY, which works
  before WiFi assigns an IP — clients can connect once WiFi is up)
- Log now shows "(waiting for WiFi)" if started before WiFi connects

### WiFi Disconnect/Reconnect Tracking
- Added `disconnect_count` and `reconnect_count` to wifi_manager.c
- Disconnect events increment counter in `wifi_event_handler`
- Reconnection detected when DHCP IP assigned after a prior disconnect
- New API: `wifi_manager_get_stats(uint32_t *disconnects, uint32_t *reconnects)`
- `/api/status` now includes `wifi_disconnects` and `wifi_reconnects`
- Heartbeat log: `dc=0 rc=0` appended to periodic status

### M5 Status
M5 milestone is now functionally complete. The only remaining item
(24-hour continuous operation) requires unattended runtime and is
deferred to physical testing.

## Files Changed
