# Day 9 — Stability & Health Monitoring (M5 Started)

## Goals
1. Hardware watchdog timer — auto-reset on hang
2. System heap monitoring — track DRAM usage
3. WiFi RSSI reporting — signal strength in status API + HUD

## Completed

### Hardware Watchdog Timer
- Added 30-second hardware watchdog (ESP32 WDT stage0→stage1 reset)
- Feeds from main heartbeat loop (proves main thread liveness)
- Starts AFTER all init completes (WiFi connect can block 10-30s)
- `WDT_OPT_PAUSE_HALTED_BY_DBG` set for JTAG safety
- Boot log confirms: `Watchdog started (timeout 30000 ms)`

### System Heap Monitoring
- `CONFIG_SYS_HEAP_RUNTIME_STATS=y` enables runtime stats
- `/api/status` now reports `heap_free` and `heap_used` (DRAM system heap)
- Idle values: ~27KB free, ~86KB used
- Frontend HUD displays memory usage in KB

### WiFi RSSI Reporting
- New API: `wifi_manager_get_link_info(int *rssi, unsigned int *channel)`
- Uses `net_mgmt(NET_REQUEST_WIFI_IFACE_STATUS)` gated on connection state
- `/api/status` reports `rssi` (dBm) and `channel`
- Frontend HUD displays WiFi signal strength
- Heartbeat log: `Heartbeat: uptime=38s WiFi=up rssi=-48 ch=6`

## Key Technical Decisions
- **Main-only WDT feeding**: Proves main-loop liveness, not all threads. Acceptable
  for current architecture (single http_thread handles everything). Multi-thread WDT
  feeding would add complexity without proportional benefit.
- **System heap only**: Reports DRAM system heap, not PSRAM pools. Labeled clearly
  to avoid confusion. PSRAM is used for camera frame buffer only.
- **RSSI gated on connection**: Returns 0/0 when WiFi disconnected, avoiding stale values.
