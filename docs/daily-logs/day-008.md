# Day 8 — WebSocket Video Stream Fix

## Goal
Complete M4: WebSocket Video Stream — fix browser handshake rejection.

## Problem
WebSocket handshake implementation was present (SHA-1 + Base64 Accept computation,
binary frame sender, Canvas frontend). Raw socket tests passed, but browsers and
Python websocket libraries rejected the handshake with "Incorrect Sec-WebSocket-Accept".

## Investigation
1. Verified SHA-1 output against Python hashlib, openssl, shasum — all matched
2. Set up TCP proxy to capture actual request/response bytes — Accept values matched
3. The "raw socket" verification was computing expected Accept using **the same wrong GUID**
4. Inspected the Python `websockets` library source code and found the correct GUID

## Root Cause
**Wrong WebSocket magic GUID in server code.**

- Our code: `258EAFA5-E914-47DA-95CA-5AB5AC45E8B0` ❌
- RFC 6455: `258EAFA5-E914-47DA-95CA-C5AB0DC85B11` ✅

The custom SHA-1 and Base64 implementations were correct — the input constant was wrong.
All manual verification passed because we compared against the same wrong GUID.

## Fix
Single line change: corrected the `ws_guid[]` constant in `src/http_server.c`.

Also increased `HTTP_RECV_BUF_SIZE` from 512 to 1024 to safely accommodate
browser HTTP headers (User-Agent, Accept-*, etc. can exceed 512 bytes).
