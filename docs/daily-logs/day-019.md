# Day 19 — Bug Fix: FPS, Resolution Switch, WebSocket

## Goal
Fix 3 user-reported issues:
1. Resolution switch "not working" (WS page doesn't reconnect after change)
2. FPS very poor (~1.7 fps, should be ~7+ fps)
3. WebSocket "not working" (actually works but crippled by low FPS + no reconnect)

## Root Cause Analysis

### Poor FPS (~1.7 fps)
- `STREAM_SKIP_FRAMES = 2` wastes ~132ms/frame (2 VSYNCs skipped before each capture)
- `MJPEG_FRAME_DELAY_MS = 50` and `WS_FRAME_DELAY_MS = 50` add 50ms dead time
- Total per frame: ~320ms (skip) + 50ms (delay) = ~370ms → ~2.7fps theoretical

### Resolution switch
- API works correctly (confirmed: resolution changes via /api/resolution/{res})
- WS page: WebSocket not reconnected after resolution change → appears broken
- Index page: MJPEG stream src is reloaded after 1s → works

### WebSocket
- Fundamentally works (WS: open confirmed) but limited by poor FPS
- After resolution change, stream is force-stopped but WS not reconnected

## Fixes

### 1. FPS improvement (stream_handler.c + cam_i2s_capture.c)
- `STREAM_SKIP_FRAMES`: 2 → 0 (no skip in steady-state streaming)
- `WARMUP_FRAMES`: 30 → 10 (faster first frame / resolution change recovery)
- `MJPEG_FRAME_DELAY_MS`: 50 → 10
- `WS_FRAME_DELAY_MS`: 50 → 10

### 2. WS page reconnect (html_pages.h)
- After setRes(), close WS → onclose auto-reconnect retries every 2s
- Reset FPS counter on resolution change
