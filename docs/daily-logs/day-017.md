# Day 17 — Code Refactoring: Module Splitting

## Goal
Scheduled refactoring day (every 5 days). Split 3 oversized source files into focused modules while maintaining identical runtime behavior.

## Work Done

### Module Splits

| Original File | Lines Before | → | New Files | Lines After |
|---|---|---|---|---|
| `cam_i2s_capture.c` | 644 | → | `cam_i2s_hw.c` + `cam_i2s_capture.c` | 518 + 119 |
| `http_server.c` | 665 | → | `http_api.c` + `http_server.c` | 308 + 338 |
| `camera_init.c` | 441 | → | `camera_sccb.c` + `camera_config.c` + `camera_init.c` | 47 + 228 + 160 |

### Architecture Decisions

- **cam_i2s_hw.c**: Phase-level API (prepare/dma_start/extract_start/stop) keeps all volatile/ISR state private. Prevents cross-file volatile access races.
- **http_api.c**: All response templates, request parsing, and API handlers extracted. HTTP server retains only socket management and thread loop.
- **camera_sccb.c**: I2C register transport layer (read/write/write_regs).
- **camera_config.c**: Resolution table, JPEG config, `camera_set_resolution()`.

### Key Fixes During Refactoring

- `sizeof()` on `extern const char[]` fails (incomplete type) → replaced with `strlen()` in http_server.c
- Flash at offset 0x0 causes boot loop → must always use `west flash` (writes at 0x1000)
